## BL-001 テストへ引き込むソースの取り込み方がリンクからコピーへ切り替わると、残っている古いリンクのためにビルドが失敗する

### 概要と問題点

- **現状の事象**: Linux で、テスト ディレクトリへ引き込むソース (`TEST_SRCS`、`ADD_SRCS`) の取り込み方がシンボリック リンクからコピーへ切り替わったとき、以前のビルドが作ったリンクが残っていると、ビルドが次のエラーで失敗します。

    ```text
    cp -p ../../../../../prod/libsrc/cplat/console/console.c console.c
    cp: '../../../../../prod/libsrc/cplat/console/console.c' and 'console.c' are the same file
    make[5]: *** [.../framework/makefw/makefiles/makesrc_c_cpp.mk:559: console.c] エラー 1
    ```

    取り込み方は `makefiles/_collect_srcs.mk` が決めます。Linux では、inject ファイル (`<対象ソース名>.inject.c`) もフィルター ファイル (`<対象ソース名>.filter.sh`) もないソースをリンクで引き込み (`LINK_SRCS`)、どちらかがあるソースをコピーで引き込みます (`CP_SRCS`)。そのため、既存のテスト ディレクトリへ inject ファイルを追加すると、そのソースはリンクからコピーへ切り替わります。  
    コピーの規則 (`makefiles/makesrc_c_cpp.mk` の `generate_cp_src_rule`) は、コピー先に古いリンクが残っている場合を扱っていません。コピー先のリンクはコピー元を指しているため、`cp` はコピー元とコピー先を同じファイルと判定して失敗します。  
    引き込んだソースは `.gitignore` の対象のため、`git status` には現れず、原因に気付きにくい状態です。

- **再現した手順**: 2026-11-20 に、`app/cplat` のコミット `8bd35e72` (`test/src/libcplatTest/console/consoleTest/` に inject ファイルがない) でビルドした作業ツリーを、`6e3498db` (コミット `9b16dc2a` で `console.inject.c` と `console.inject.h` を追加済み) へ更新し、`make -C app/cplat` を実行して発生しました。`consoleTest/console.c` は、2026-10-04 に作られたリンクのまま残っていました。リンクを手で削除すると、次のビルドでコピーされました。
- **本来あるべき姿**: 取り込み方が切り替わっても、利用者が手で後始末をせずにビルドできることです。コピーの規則は、コピー先が古いリンクであれば、置き換えてからコピーします。

### 影響範囲とリスク

- **影響対象**: makefw でテストをビルドするすべての app の、Linux の既存の作業ツリー。既存のテスト ディレクトリへ inject ファイルまたはフィルター ファイルを追加する変更を取り込んだ利用者が対象です。新しく取得した作業ツリーと CI では起きません。Windows は、inject ファイルの有無によらずコピーで引き込むため、切り替わりが起きません。
- **放置した場合のリスク**: inject ファイルを追加する変更が取り込まれるたびに、既存の作業ツリーを持つ利用者のビルドが失敗します。エラーの文言から原因 (古いリンク) を読み取りにくく、調査に時間を取られます。並列ビルドでは、失敗が同じ階層のほかのテストのビルドを中断させます。
- **未確認の事項**: 逆向きの切り替わり (inject ファイルを削除して、コピーからリンクへ戻る場合) で、残っている古いコピーがどう扱われるかは確認していません。`_collect_srcs.mk` は、カレント ディレクトリにある通常のファイルを `DIRECT_SRCS` (フォルダーに存在するソース) として扱うため、古いコピーが更新されないまま使われ続ける可能性があります。

### 推奨される対応策

- **恒久対応案**: `generate_cp_src_rule` で、コピーの前に、コピー先がシンボリック リンクであれば削除します (フィルター ファイルを通す経路も同じ扱いにします)。あわせて、逆向きの切り替わりを確認し、古いコピーが残る場合の扱いを決めます。makefw の単体の確認 (取り込み方の切り替わりを再現するテスト) を追加します。
- **参考情報**: `framework/makefw/makefiles/_collect_srcs.mk` (`CP_SRCS`、`DIRECT_SRCS`、`LINK_SRCS` の判定)、`framework/makefw/makefiles/makesrc_c_cpp.mk` (`generate_cp_src_rule`、`generate_link_src_rule`)、`framework/testfw/docs/how-to-test.md` の「ファイル内に閉じた関数は inject で到達させる」、`app/cplat` のコミット `9b16dc2a` (`test/src/libcplatTest/console/consoleTest/console.inject.c` の追加)。
