## LADR-002 リンクからコピーへの切り替わりで残る古いリンクの扱い

決定者: Tetsuo Honda  
最終更新日: 2026-11-25

### 背景と課題

Linux では、テスト ディレクトリへ引き込むソースに inject ファイルまたはフィルター ファイルが加わると、引き込み方がシンボリック リンクからコピーへ切り替わります。以前のビルドが作ったリンクが残っていると、コピーの規則 (`makesrc_c_cpp.mk` と `makelibsrc_c_cpp.mk` の `generate_cp_src_rule`) が正しく動きません。古いリンクを取り除く方式を決める必要がありました。

### 得られた事実

- 同じ `generate_cp_src_rule` が `makesrc_c_cpp.mk` と `makelibsrc_c_cpp.mk` の 2 つにあります (ソースの読解)。
- 一時ディレクトリへの複製で、古いリンクが残ったままの次の事象を再現しました (2026-11-25、主エージェントの事前再現)。
    - inject ファイルを追加すると、`cp: ... are the same file` で失敗します。
    - inject ファイルを追加した後にコピー元を編集すると、コピーの規則が起動せず、リンクのまま inject なしでビルドが成功します。
    - フィルター ファイルを追加すると、リダイレクトがリンクを辿り、コピー元が 0 バイトになります。`make` は警告なしに成功します。
- 解析時に古いリンクを検出して再生成を強制し、レシピの先頭でコピー先を削除する方式を一時ディレクトリの複製に試作し、上の 3 つの事象が起きないこと、続けてのビルドで再生成が繰り返されないこと、`make -n` でファイルが変わらないことを確認しました (2026-11-25)。
- 既存の `source_classification_selftest.py` は、ドライ ランが構成ファイルを書かないことを確認しています。

### 決定

- Linux の解析時に、コピーの対象 (`CP_SRCS`) と同名のシンボリック リンクがカレント ディレクトリにあるかを検出し、該当するコピーの規則に、常に再生成させる前提条件を加えます。
- コピーの規則のレシピの先頭で、コピー先を削除してから、コピーまたはフィルターを行います。
- `make -n` (ドライ ラン) では、ファイルを削除しません。
- `makesrc_c_cpp.mk` と `makelibsrc_c_cpp.mk` の両方に同じ修正を入れます。

## LADR-004 bin_test の文字コードの指定の修正範囲

最終更新日: 2026-11-25

### 背景と課題

規範 `app/general/docs/python-text-encoding-guideline.md` は、`encoding="utf-8"` の明示を求め、デコード エラーを隠す目的の `errors="replace"` を禁じています。BL-029 は前者の漏れだけを対象にしており、後者も同時に直すかを決める必要がありました。

- `errors="replace"` の 17 か所の除去は、この案件では対策せず、この案件の残課題一覧の BL-001 として記録します。

## LADR-008 コピーからリンクへの切り替わりで残る古いコピーの扱い

決定者: Tetsuo Honda  
最終更新日: 2026-11-25

### 背景と課題

Linux では、inject ファイルやフィルター ファイルを削除すると、引き込み方がコピーからリンクへ戻ります。以前のビルドが作ったコピーは通常のファイルとして残り、「ローカル実体の優先」により `DIRECT_SRCS` としてそのまま使われます。この古いコピーの扱いを決める必要がありました。

### 得られた事実

一時ディレクトリへの複製での実測と、ソースの読解で確認した内容です (2026-11-25)。

- フィルター ファイルを削除した後は、コピー元を編集しても `make` が「行うべき事はありません」で終わり、編集が警告なしに無視されます。`ADD_SRCS` の inject ファイルを削除した場合も同じです。
- `TEST_SRCS` の inject ファイルを削除した後は、古いコピーに残る `#include "<名前>.inject.c"` のため、コンパイルが失敗します。
- `make clean` は、外部のディレクトリにあるソースと同名のファイルを分類によらず削除します。利用者が意図して置いた同名の実ファイルも削除されます。
- リポジトリには、外部のソースと同名の実ファイルをテスト ディレクトリで Git 管理している例はありません。
- Windows は `_collect_srcs.mk` の `EXTERNAL_SRCS` で、外部のディレクトリにあるソースと同名のローカル実体を `DIRECT_SRCS` から外し、コピーの対象へ戻しています。
- Linux でも同じ判定を行い、解析時に検出してリンクの規則を必ず実行させる方式を試作し、inject ファイルの削除後の次のビルドでリンクへ戻ること、続けてのビルドで再実行が繰り返されないこと、同じディレクトリを指す指定は置き換えないこと、既存の `source_classification_selftest.py` が期待値の変更だけで成功することを確認しました。

### 決定

- Linux と Windows のどちらでも、外部のディレクトリにあるソース (参照先のディレクトリがない指定を含む) と同名のローカル実体を、`DIRECT_SRCS` から外します。判定には、両 OS で同じ共通関数を使います。
- Linux では、外したソースをリンクで引き込み、該当するリンクの規則を解析時の検出により必ず実行させて、次のビルドでローカル実体をリンクへ置き換えます。`make -n` ではファイルを変えません。
- 同じディレクトリを指す指定の実ファイルは、これまでどおり `DIRECT_SRCS` として扱います。
- Linux の「ローカル実体の優先」は廃止し、`source_classification_selftest.py` の期待値と `framework/makefw/docs/makeparts.md` の記述を改めます。
