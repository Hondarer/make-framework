# GCC 自動 PCH の include 解決プローブを objdir 配下へ配置する最終仕様

検討 ID: gcc-pch-resolve-probe-20261115

版: 1

状態: 承認済み

対応する前提合意版: 4

## プローブをビルド中間物の領域へ配置する

Linux / GCC の自動 PCH 準備処理が生成する include 解決用プローブを、ソース ディレクトリから `objdir` 配下へ移します。  
標準の `OBJDIR` (`obj` または `obj/<構成>`) では、既存の Git 無視設定、ビルド署名の除外、`make clean` の削除範囲を利用します。  
`.gitignore` とビルド署名の走査処理は変更しません。

任意の独自 `--objdir` に対する Git 無視や署名除外は保証対象外です。  
すでにソース ディレクトリへ残存するプローブは自動削除しません。  
Git のステージング、コミット、アンステージ、スタッシュは作業に含みません。

## 一意な空の一時ディレクトリで生成と削除を管理する

`gcc_pch.py` の `prepare()` で求めた `objdir` を、`_usable_prefix()` を経由して `_resolve_includes()` へ渡します。  
`_resolve_includes()` は `objdir` の存在を確保し、`tempfile.TemporaryDirectory(prefix=".makefw-pch-resolve-", dir=objdir)` 相当で一意な空のディレクトリを作成します。  
プローブ名は、そのディレクトリ内の `probe.c` とします。  
PID だけを名前にした既存ディレクトリの再利用は行いません。

プローブへの UTF-8 書き込みと GCC 実行を一時ディレクトリの管理範囲へ含め、正常終了と Python 例外時に後始末を行います。  
GCC の失敗時は、既存の動作と同様に自動 PCH を使用せず通常コンパイルへ戻します。  
ファイル操作の例外は既存のエラー処理に従い、一時ディレクトリが作成済みの場合は、その後始末を実施します。

`finally` が実行されない強制終了では残存し得ますが、新規プローブは `objdir` 配下へ限定します。  
決定キャッシュと共有 PCH の既存ロックを維持します。

## 探索パスを追加せずに先頭の引用符 include を記述する

ソース先頭の無条件 include 接頭辞を、既存と同じ順序でプローブへ記述します。  
引用符形式の `"name.h"` については、次の規則を適用します。

1. `source_directory / "name.h"` に通常のファイルが存在する場合、その絶対パスを引用符 include として記述します。
2. 通常のファイルを指すシンボリック リンクも対象にします。ただし、実体側へ `resolve()` して親ディレクトリを変更しません。
3. ソース側で見つからない場合は元の引用符 include を維持し、既存の GCC の探索パスに従わせます。
4. 山括弧 include は元の記述を維持します。

GCC に渡すユーザー フラグ、環境変数、作業ディレクトリを維持し、追加の `-iquote` や `-I` を付与しません。  
空のプローブ ディレクトリによって、`objdir` 直下の同名ヘッダーが先に選択されることを防ぎます。  
読み込まれたヘッダー内部の引用符 include は、そのヘッダー自身のディレクトリと既存の探索パスで解決させます。

現在ファイルのディレクトリ探索を抑止する `-I-` など、上記の探索前提が成立しない指定は通常コンパイルへ戻します。  
既存の `-include`・`-imacros` による無効化も維持します。

> [!NOTE]
> GCC の引用符 include は現在ファイルのディレクトリを優先します。
> `#line` は include の探索基準を変更しません。
> 根拠は [GCC Search Path](https://gcc.gnu.org/onlinedocs/cpp/Search-Path.html) と [GCC Line Control](https://gcc.gnu.org/onlinedocs/cpp/Line-Control.html) です。

## 変更対象と永続的な知見の反映先

- `framework/makefw/bin_internal/gcc_pch.py`: プローブの配置、引数の受け渡し、include の記述調整、後始末、探索前提が成立しない指定の無効化を実装します。
- `framework/makefw/bin_test/gcc_pch_selftest.py`: 下記の配置・後始末・探索条件を回帰確認へ追加します。
- `gcc_pch.py` の対象関数のコメント: 空の一時ディレクトリと先頭 include の絶対パス化が必要な理由を記載します。探索規則の根拠 URL を `see: <URL>` 形式で残します。

利用者向けの設定追加はありません。  
一時プローブの内部設計は対象関数のコメントへ反映し、検討の経緯や実験の失敗履歴は製品コメントへ転記しません。  
Windows / MSVC の PCH 処理は変更しません。

## 局所検証と受入条件

既存の `gcc_pch_selftest.py` 全 21 項目を WSL / Linux で実行し、成功することを確認します。  
追加した確認項目では、次の条件を満たすことを検証します。

- GCC 呼び出し中にプローブを観測し、`objdir` 配下の一時ディレクトリへ生成され、ソース側へ生成されないこと。
- 正常終了、GCC の非ゼロ終了、プローブ書き込みの例外で、一時ディレクトリが削除されること。
- C と C++ の双方で、ソース側と `objdir` 側に同名ヘッダーがあっても、ソース側の先頭引用符 include が選択されること。
- 入れ子の引用符 include に対して、ソース ディレクトリが既存の探索パスより優先される変化がないこと。
- ソース側にヘッダーがない場合の既存 `-iquote`・`-I`、山括弧 include、およびソースと異なる作業ディレクトリで、現行と同じヘッダーへ解決されること。
- ファイルを指すシンボリック リンクの親ディレクトリを維持できること。
- `-I-` 等の探索前提が成立しない指定で、自動 PCH を使用せず通常コンパイルへ戻ること。
- 標準の `obj/` 配下のプローブが、適用される Git 無視規則と署名走査の除外条件に該当すること。Git の書き込み操作を伴わない確認方法を使用すること。

警告確認項目の `.warn` に意図した `pch-marker` が残ることと、変更に起因する予期しない警告がないことを確認します。  
追加の個別 app ビルドや framework 全体テストは実施しません。
